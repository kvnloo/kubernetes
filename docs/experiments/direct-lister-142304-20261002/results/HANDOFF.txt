Discussion recontextualization established so far
- The original opposition concerned maintaining a separate read path and
  future semantic drift; best-effort mutation detection was insufficient.
- Current copy tests support isolation at the tested conversion boundary.
  They do not answer live-cache provenance, storage defaulting or system gain.
- Current PSA adapter drops ctx, as the existing informer API did too. Its
  context-aware direct extension is not reached through that adapter.
- Existing informer transform removes managedFields; direct reads retain it.
- PR142304 explicitly calls itself stage 1 of 2 and leaves node-authorizer
  informer elimination to a follow-up. Our lifecycle result agrees with that
  limitation; it is not evidence the author expected stage 1 to eliminate it.
- Issue142223 motivates fewer update/relist allocations and burst recovery,
  not merely faster individual lister reads. Its >4k QPS result combines
  several interventions; our warm read microbench does not isolate that claim.
- A prior issue142223 comment already proposed A1/burst/A2 hysteresis testing.
  Refine that existing proposal rather than presenting it as a new discovery.

Candidate follow-ups (proposals; NOT_RUN; NOT_PREREGISTERED)
1. Real Pod REST/Cacher/codec versus informer differential replay, including
   omitted-default fixtures, ordinary errors and source-preservation oracles.
2. Allocation attribution with identical returned values: managedFields
   transform placement, explicit normalization, fixture setup excluded.
3. Actual consumer lifecycle/readiness matrix, counting Pod informer List/Watch
   and actual direct calls for production consumer wiring. All other resources
   and their readiness prerequisites must remain active.
4. Net resource experiment: lister strategy x event-consumer presence x
   update/read workload; include update propagation, retained heap and GC.
5. Bounded watch-restart/relist and A1/burst/A2 recovery experiments in isolated
   test processes after the evaluator's counters and recovery gates qualify.
6. Startup/cache-catch-up/error/fallback behavior using benign fixtures, exact
   call counts and cancellation/deadline outcomes; distinguish pre-sync cache
   results from post-sync contract comparisons.

Next runner should begin with N1's real cache/codec parity trial, then N6's
bounded startup/version cases and N3's consumed-route qualification. Existing
Pod REST helper uses UndecoratedStorage; Cacher helper waits until ready.
