storage-codec comparison before adding more synthetic benchmark repetitions.
The current copy and context experiments establish component boundaries.
They do not establish codec/defaulting parity or net update-path savings.

N1. Real storage differential (first)
Use a root-repository integration test sharing one isolated etcd prefix between
the direct path and normal loopback client/informer. Compare exact UID/RV
snapshots, ordinary Get/List results and supported omitted-default fixtures.
Record raw fields separately from the known GVK/managedFields differences.
Never normalize away spec/status defaults. Confirm actual cache/backend calls.

Critical harness traps: the existing Pod REST newStorage helper uses
UndecoratedStorage, so it does not exercise Cacher. The staging Cacher helper
waits for initialization, so it does not exercise startup. Staging tests cannot
import the root direct package; cross-path integration belongs in root tests.
REST Get is not itself an explicit defaulting hook; trace and record the codec.

N2. Fair transform/copy allocation attribution
Compare cached-trimmed/direct-output-trimmed and cached-retained/direct-retained
as separate equal-output groups. Use current managedFields sizes and warm
read shapes. Qualify exact values and source ownership before measuring.
Trimming after conversion may restore representation but still pay copy costs.
This distinguishes a representation mismatch from a conversion-cost mechanism.

N3. Production consumer routes and readiness
Exercise the actual initialization/adapters, with Pod List/Watch, direct read,
fallback and handler-sync receipts. Keep namespace, device-class and other
prerequisite informers alive. Verify a bounded update reaches any required Pod
event handler. The stage-1 node graph still consumes Pod events; this is an
explicit stage boundary. Do not infer informer elimination from lister-only
factory tests. PSA adapter context handling must be measured at its used route.

N4. Net resources under updates and reads
Factor cached/direct lister x event consumer absent/present. Start update-only,
then read-only, then fixed mixed successful operations. Measure allocation
rate, retained heap under a fixed GC protocol, CPU/GC, propagation lag, actual
watch/relist work and verified outcomes. Follow with isolated server trials.
This tests the issue's update-propagation motivation. Do not attribute its
combined-optimization throughput result to direct listers.

N5. Bounded recovery, refining the existing issue proposal
First distinguish resumed watch from full relist using actual route/RV/status
receipts. Then compare A1/B/A2 with a small registered perturbation and a
no-perturbation control. Measure allocation peak/area and recovery, preserving
feature gates and WatchList negotiation. The issue already proposed this
shape; the new value is mechanism attribution and calibrated stop rules.

N6. Startup, freshness and benign fallback
Own construction for pre-ready tests. Separate pre-registration, cache-ready
and informer-synced stages, then create/update/delete/recreate benign Pods with
identity/version barriers. Count token getter object-read fallback calls only.
CacheDelegator.Get falls back to storage before cache readiness; GetList is
option-dependent and can instead reach Cacher's not-ready error. Do not predict
all startup outcomes from Cacher alone. Compare synchronized results only
after the declared barrier; report permitted earlier staleness separately.
